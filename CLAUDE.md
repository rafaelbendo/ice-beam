# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**ICE-BEAM** (ICESat-2 Bluff Erosion Assessment Method): the `is2retreat` Python package, which
measures Arctic coastal bluff erosion on the North Slope of Alaska from ICESat-2 ATL06-like
elevation profiles generated by [SlideRule](https://slideruleearth.io).

The core scientific problem: ICESat-2 repeat tracks rarely cross the coastline exactly
perpendicular to it, and different repeats of the same reference ground track (RGT) are offset
laterally from each other. Measuring shoreline position change directly along-track over- or
under-estimates true retreat depending on the crossing angle. The pipeline clusters nearby
repeated beam passes, estimates the local crossing angle, and applies a **GIE** (geometric)
correction to turn along-beam bluff-position change into cross-shore Net Shoreline Movement
(`NSM`), following USGS DSAS (Digital Shoreline Analysis System) conventions for its outputs.

The package is a port of the final research notebook (v21, SlideRule 5 m ingestion) and its
`gie_postprocess_dynamic.py` module, and reproduces the published results value for value.
Changes to the science logic should keep that property unless the change is intended.

Data flow per track: inputs → geometry → preprocessing → (for each bias tolerance:
clustering → angles → bias → bluff → metrics) → GIE → outputs.

## Environment and running

```bash
conda env create -f environment.yml && conda activate icebeam && pip install -e .

is2retreat --config configs/north_slope.toml --track 0129            # one track
is2retreat --config configs/north_slope.toml --tracks-file configs/tracks_filtered.txt
is2retreat ... --source cache|sliderule|auto --outdir DIR --set SIZE_LIMIT_M=90
```

`sliderule_cache_dir` in `configs/north_slope.toml` is machine-specific; point it at a local
folder. SlideRule pulls are cached there as `<track>/ATL06_5m.gpkg`, and `--source auto`
(default) reuses the cache when it exists. A track that can't be processed raises `TrackSkipped`
and the batch moves on. Track ids are 4-digit zero-padded RGT numbers.

Dashboard: `streamlit run dashboard/app.py`. The optional historical-DSAS layer on the Erosion
Results page reads `dashboard/data/historical_dsas/` (gitignored, not distributed).

Python API: `paths, params = load_config(...)`, `run_track(track_id, paths, params,
write_outputs=False)` returns a `TrackResult` (DSAS tables, GIE result, `inputs`).

There is no test suite. Lint with `python -m pyflakes src/is2retreat`. To verify a change to
pipeline logic, run a few tracks from the cache into a scratch `--outdir` before and after the
change and compare the CSVs value by value (e.g. tracks 0129, 0495, 0564, 0419; 0007 is skipped).
Don't point test runs at a results folder you want to keep: writes merge into existing tables.

## Output tables

Six CSVs in `outdir`, suffixed with the resolution (`_5m`); full column descriptions in the
README. Keys: `track_id`, `bias_tolerance`, `gt_family`, `cluster_id` (numbered per track AND
bias tolerance). Positions increase landward, so negative NSM/EPR/LRR = retreat.

| File | One row per |
|---|---|
| `cluster_metrics_measured_5m.csv` | cluster (measured DSAS metrics) |
| `cluster_metrics_gie_5m.csv` | cluster (measured + GIE-corrected; main result) |
| `interval_changes_measured_5m.csv` | consecutive date pair in a cluster |
| `interval_changes_gie_5m.csv` | consecutive date pair, measured + corrected |
| `bluff_positions_gie_5m.csv` | bluff position (beam, date) with GIE terms |
| `beam_angles_5m.csv` | member beam's crossing angle |

Earlier results used older names (`DSAS_5m.csv`, `DSAS_GIE_AllBiasTol_5m.csv`,
`..._Intervals_5m.csv`, `..._BeamDetails_5m.csv`, `DSAS_BeamAngles_5m.csv`) with the same
columns. Writes are file-locked and de-duplicated on the keys, so re-running a track replaces its
rows; date key columns must be parsed as dates before de-duplication or re-runs duplicate rows.

## Parameters (`Params` in `config.py`)

Defaults: SlideRule 5 m resolution / 40 m segments, 2019-01-01 → 2025-12-31; `BIAS_TOLERANCES`
0.1–0.7 m; `X0` = `XM` = 500 m; `SIZE_LIMIT_M` = 180 m; `MIN_PROFILES_PER_CLUSTER` = 2;
positional uncertainty 4.8 m. The extraction box is `HALF_ALONG_M` = 300 m **along the beam**
(i.e. cross-shore) and `HALF_ACROSS_M` = 600 m **across the beam** (i.e. alongshore).

`gie.get_local_coastline_slope_sign()` has an intentionally inverted sign rule, validated
against hand-derived cases; don't "simplify" it without re-validating.

## Domain vocabulary

- **RGT** — Reference Ground Track (ICESat-2 repeat orbit path id); 4-digit zero-padded (`0129`).
- **`gt_family`** — ICESat-2 beam-pair group (`gt1`, `gt2`, `gt3`), each a strong/weak beam pair.
- **Beam** (`beam_id`) — one beam of one cycle, e.g. `sliderule_0129_gt1l_cyc03_20190406`.
- **Cluster** — beam passes over the same piece of coast, grown laterally from a boundary beam
  while `|elev(X0) − elev_ref(X0)| ≤ bias_tolerance`, dates don't repeat, and width stays within
  `SIZE_LIMIT_M` (see `clustering.py`).
- **NSM** — Net Shoreline Movement (DSAS): first − last position. `NSM_measured` is along-beam;
  `NSM_corrected` / `bluff_x_gie` are after the GIE correction.
- **GIE** — geometric correction for oblique crossings:
  `NSM_geo = coast_slope_sign · d_signed · tan(90° − angle)`.
